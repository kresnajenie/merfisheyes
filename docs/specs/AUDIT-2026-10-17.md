# Audit of loading, querying and rendering, 2026-10-17

What the viewer does today, read off the code on `develop` (`7a60669`, after
PR #150 points element and #151 shapes) and the real stores on the public
bucket. It is the "before" of the plan in `docs/PHILOSOPHY.md` and the
reason for each step in `docs/specs/BUDGETS.md`. Paths are repository
paths; line numbers were right on that commit.

## 1. Loading and querying

### Opening a store

- By URL: the root `zarr.json` (with the consolidated metadata) is fetched
  **three times** — `resolveUrl.ts`, `store.ts:78`, and the table adapter's
  own `zarr.open.v3`. The consolidated metadata is used only to list keys;
  every node is opened through its own `zarr.json` (no `withConsolidated`).
- By dataset id: `/api/datasets/{id}/list` returns **every key** of the
  store (38,030 for the ten-section store) in one JSON; each object then
  costs a presign call plus the S3 GET; the presigned-URL cache is per store
  instance with no in-flight dedup.
- The points element's `zarr.json` is read two to three times
  (`points.ts:149`, `:163`, `image.ts:103`); `obsm/spatial`'s twice.
- `mapping.json` is read in three places (`resolveUrl`, `loadSpatialDataMolecules`, `dataset-links`).
- Two zarrita versions: 0.5.1 for the h5ad-zarr path, 0.7.5 for `lib/spatialdata/`.

### Cells

- Coordinates and one obs column up front; other columns lazily on the main
  thread; expression per gene through CSC `X` (or a `layers/X_csc` copy).
  One gene = `indptr` once, then the overlapping chunks of `indices` and
  `data` (about 17 small reads on the skin store). CSR without a CSC copy
  reads the whole matrix per gene.
- `geneExprCache` is unbounded and holds `number[]` per gene; concurrent
  requests for one gene are not deduplicated.

### Points element (`lib/spatialdata/points.ts`, `PointsLayer.ts`)

- Writer: chunks of 65,536 rows, shards of 64 chunks; `x`, `y` float32 with
  blosc zstd (2.1–3.2 B per row compressed on the real stores); index arrays
  unsharded.
- Reader: a 512 MB LRU of compressed bytes with in-flight dedup; unbounded
  maps for index slices and run tables; `id` and `tile_rows` never read.
- Planner: per visible gene, `featureTiles` at **every** level, then the
  finest level whose in-view count fits an equal share of the point budget
  (`DETAIL_BUDGET` auto 15 M / more 30 M / all 64 M). One piece per tile
  row, x range snapped to a power-of-two block with one row of padding each
  side, so molecules wanted can exceed the budget.
- Loading: 6 pieces at a time, each read in 65,536-row segments one after
  another, `dims` reads per segment; uploads paced at 1 M molecules per frame.
- **No cancellation**: no `AbortSignal` reaches zarrita or `fetch`; stale
  pieces queued for views already left are still fetched (`pump` never
  checks `lastWanted`, unlike `ImageLayer`).
- Molecule cache `CACHE_POINTS` 40 M (about 17 B GPU + 15 B CPU each), idle
  pieces evicted oldest first; pieces in use never, so "All" (64 M) exceeds it.
- Hidden genes get no budget share in the code, though two comments say they keep it.
- `fetchRange` merges nothing; one request per range; shard index 1,028 B
  suffix read per new shard.

### Legacy molecules (`genes/{gene}.bin.gz`)

- `fromS3` and `fromCustomS3` are near-identical (~350 lines each), with the
  whole-file (pako) and streamed (`DecompressionStream`) paths duplicated and
  the name sanitiser copied three times. Threshold
  `SINGLE_MOLECULE_STREAM_THRESHOLD` = 100,000 (docs said 2 M).
- Three molecule paths coexist: points element (only with cells), per-gene
  files (whole in the cell scene, streamed in the SM scene before PR 1),
  local parse.

### Shapes and image

- Shapes: the **whole** GeoParquet (31 MB on atera) on the first zoom-in,
  decoded in a fresh worker per load; a 100 µm grid; 60 k cap; element
  found by name (`cell_boundaries`, `cell_polygons`, `cells`).
- Image: finest level with pixel ≥ 0.75 × screen pixel and ≤ 12 chunks in
  view, plus every chunk of the coarsest level; one request per chunk per
  visible channel; 4 concurrent; 512 MB decoded-texture cache (CPU copy
  kept, so double); stale queue entries skipped, in-flight not aborted.

### Concerns implemented more than once

Three ways to open a store (id, URL, files) and three more for images; two
local file stores; three "403/404 means missing" fetchers and two Range
styles; seven caches with different units; five cancellation styles
(AbortController, `cancelled` flags, `disposed` + identity, `lastWanted`,
none); concurrency limits 6, 4 and none; three visible-rectangle copies;
three level-of-detail schemes; three spatial grids.

## 2. Rendering

- **Every scene renders every frame** (`scene-manager.ts` without
  `idleFps`), and `ImageLayer`, `PointsLayer` and `ShapesLayer` each run
  their own `requestAnimationFrame` loop with per-frame work (unprojects,
  `chunksInView` allocations, loops over all tiles, eviction sums). The
  `idleFps`/`invalidate` mechanism exists but only the labelled viewer uses it.
- **Constants stored per vertex**: cell cloud 32 B/point (position, colour,
  size, alpha as float32); molecule clouds 32 B of which 20 B are constant
  per cloud; points-layer chunks 17 B of which 5 B constant. The streaming
  cloud allocates and uploads 32 B × capacity before data arrives.
- **A slider tick repaints everything**: `restyle` refills every chunk's
  colour when only `dotSize` changed; the overlay and SM scene did the same
  before PR 1. A cell-viz tick (alpha, scale min/max, multipliers, colormap,
  selection) re-extracts the gene column (`Array.from` of N), runs a
  percentile, allocates two or three N-length arrays and a small array per
  point, and creates **new** GL buffers of 20 B × N; old buffers wait for GC;
  no stale-run guard; cascades into a full shapes rebuild.
- **Hover**: brute-force `Points.raycast` over every cell, throttled to 10 ms
  (comment says 50), also while panning and with the layer hidden; stale
  bounding sphere after per-sample transforms.
- **Draw calls**: one `THREE.Points` per 65,536-row chunk in the points
  layer (≥ 229 draws at Auto, 977 at All, plus edge chunks); stand-ins from
  the previous view drawn at up to 3× size (9× area) until the whole new
  view arrives; a hidden gene shown again uploads all its chunks in one
  frame with no cap.
- **Shader**: two matrix multiplies and a `distance()` even with the filter
  off; sizes culled below 0.025 px then clamped to [1, 200] **device**
  pixels (DPR-dependent); circle `discard` defeats early-Z; `alphaTest: 0.5`
  is a **no-op** on the custom `ShaderMaterial` (no `alphatest_fragment`).
- **Ordering**: the shapes fill is transparent with depth off, so it draws
  over the opaque molecules, contrary to its comment; image tiles of every
  cached coarser level draw underneath the current one.
- **Renderer**: `antialias: true`, `preserveDrawingBuffer: true`, DPR
  uncapped and read once, resize not debounced, no `powerPreference`.
- **Leaks and churn**: the SM scene never calls `init.dispose()` (a
  `ResizeObserver` and a controls listener leak per re-init); the shapes
  triangulation cache is unbounded; `ExportBoxOverlay` sets new state objects
  every frame; `PointsStatusPanel` re-renders five times a second; the scale
  bar re-renders every frame while the camera moves.
- Correctness found on the way: the distance filter never reaches points-layer
  molecules; `extractColumnFromMatrix` case 3 computes `numCells` from a flat
  coordinate array; the SM scene called a hook after an early return.

## 4. Real stores (bucket `merfisheyes-bil`)

| Store | Molecules | Levels | Genes | Cells | Table X | Other |
|---|---|---|---|---|---|---|
| `spatialdata/12_16_2025_all_sets/` | 11,239,601,084 | 8 (tile 100 µm → 12.8 mm) | 500 | 1,587,309 | CSC, sharded | 2D, `set` column; no image, no shapes |
| `spatialdata/12_16_2025_sets/set1/` | 167,225,873 | 5 | 500 | 21,153 | CSC | no `mapping.json` (403) |
| `spatialdata/atera_breast_cancer/` | 738,289,569 | 6 | 18,028 | 170,057 | CSC | image 4×28048×46543 uint16 (1024² chunks), labels, shapes (31 MB GeoParquet); no `mapping.json`; points declare identity to `global`, shapes a 4.70588 scale |
| `spatialdata/skin_adapt_v2/` | 73,707,686 (legacy per-gene folder) | — | 5,006 | 112,551 | **CSR**, root attrs name an `X_csc` layer that is missing | points kept as parquet (not read); shapes a directory of parquet chunks (403 on `shapes.parquet`); image 4096² uint16 chunks of ~20 MB |

Per-molecule bytes on the wire (feature_major, compressed): x 2.4–3.2 B,
y 2.1–3.1 B, gene ≈ 0, id 0.1–0.7 B at level 0. A 65,536-row chunk of one
column is 150–200 KB. Index arrays per level: `feature_rows` and
`feature_tile_ptr` (n_features + 1 uint64), `feature_tile` and
`feature_tile_count` (R uint32, e.g. 23.9 M pairs at level 0 of the
ten-section store). The bucket answers 403 for a missing key and allows
only the production and standard dev ports in CORS.

## 5. Measurement before this audit

The perf suite measured `loadToRender`, `geneSelectionLatency` and
`deStatsReady` on local tiny/medium/large files only; no store with points,
shapes or an image; no bytes per view, time to first points, frame time or
memory. The fixture server logged paths, not bytes or timing. The three
layers wrote no hooks.
